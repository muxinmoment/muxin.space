# Wander Room 像素 2.5D 视觉设计规范

> 版本：v1.0  
> 状态：实施基线  
> 适用范围：`/wander/` 主场景、时间状态、互动热点与后续场景资产  
> 参考方向：黄昏像素室内、城市窗景、蓝调街巷、私人房间叙事

## 1. 设计目标

`/wander/` 不是一个展示 3D 技术的房间，而是一张可以被记住的像素游戏场景截图。用户第一眼应该先感受到房间的光线和生活痕迹，再理解四个可探索入口。

核心目标：

- 做成精致的 **2D 像素插画**，通过图层、遮挡和轻微视差获得 2.5D 深度；
- 让窗外风景成为构图焦点，让房间成为承载个人内容的叙事空间；
- 书架、照片墙、书桌、收音机四个区域必须具有一眼可辨的视觉识别；
- 黄昏是默认主视觉，清晨、午后、夜晚复用同一布局，只替换天空、光线和少量氛围资产；
- 互动增强探索，但不阻塞 `/wander/anime/`、`/wander/photos/`、`/wander/notes/` 和 `/memo/` 的直接访问；
- 桌面端像游戏截图，移动端像一张完整插画，低性能设备仍然可用。

### 1.1 参考图提炼

参考图不直接复制人物、建筑、文字、Logo 或构图，而提炼以下视觉语言：

| 参考特征 | 在 Wander Room 中的转译 |
| --- | --- |
| 室内深色、窗外暖光 | 室内使用蓝紫暗面，窗光投向地板、桌面和书架 |
| 中央大窗与城市远景 | 窗户是主构图焦点，窗外拆为天空、城市、远山三层 |
| 前景家具遮挡 | 桌沿、椅背、盆栽和散落物件形成前景层 |
| 日式街巷与电线 | 只用于夜晚或窗外远景，作为城市生活感的符号 |
| 背影和小物件叙事 | 用相机、书本、耳机、台灯和一盏远处的灯表达“有人生活过” |
| 限定色板和高密度小细节 | 先确定色板，再用像素簇而不是随机噪声增加细节 |

## 2. 技术路线

### 2.1 美术资产与网页层分工

不再让单个 SVG 承担所有美术细节，也不使用 Three.js 作为主要渲染器。

```text
320 × 180 或 480 × 270 像素基准画布
        ↓
Pillow / SVG / Canvas 绘制和整理像素资产
        ↓
导出 WebP/PNG 图层与 SVG 热点遮罩
        ↓
Astro 组合图层
        ↓
CSS transform + 少量 TypeScript 实现 2.5D 视差
```

推荐分工：

- **静态美术**：PNG/WebP 图层，使用最近邻放大，保留像素簇和边缘；
- **几何遮罩**：SVG 或 DOM，负责热点区域、焦点高亮和可访问文本；
- **动态光影**：CSS 渐变、伪元素和少量 Canvas，不实时重绘整张插画；
- **交互逻辑**：现有 `wander-diorama.ts` 继续负责镜头、热点、时间状态和进度；
- **小游戏**：现有 `wander-book-game.ts` 独立运行，不依赖美术图层内部结构。

### 2.2 基准尺寸与像素尺度

- 基准画布：`320 × 180`，16:9；需要更高细节时使用 `480 × 270`；
- 网页展示：放大至容器宽度，使用 `image-rendering: pixelated`；
- 基本像素簇：2–6 个基准像素组成，不使用单个随机噪点堆满画面；
- 线条厚度：主轮廓 2–3 基准像素，远景轮廓 1–2 基准像素；
- 重要物件的最小可辨宽度：桌面端 18 基准像素，移动端 14 基准像素；
- 不使用模糊、玻璃拟态、PBR、高光金属材质或渐变噪声滤镜破坏像素边缘。

### 2.3 资产格式

每个时间状态只替换必要图层，避免四份完整场景图片：

```text
public/wander/
├── dusk/
│   ├── sky.webp
│   ├── outside.webp
│   ├── room.webp
│   ├── objects.webp
│   ├── foreground.webp
│   └── light.webp
├── dawn/
├── day/
└── night/
```

优先使用 WebP；透明前景和需要像素边缘的图层可使用 PNG。每个资产必须有原始基准尺寸、展示尺寸和用途说明。

## 3. 构图规范

### 3.1 主构图

采用略微俯视的室内横幅构图，不追求严格透视。画面需要同时看到墙面、地面、窗外和前景遮挡。

```text
┌────────────────────────────────────────┐
│  书架/海报       大窗/城市远景          收音机 │
│  照片墙          夕阳主光源       书桌/台灯 │
│                                           │
│      地面、椅背、盆栽、桌沿、散落物件       │
└────────────────────────────────────────┘
```

推荐空间比例：

- 窗外可见区域：画面高度的 38%–45%；
- 室内后墙和家具：画面高度的 35%–42%；
- 前景遮挡：画面高度的 12%–22%；
- 书架：左侧 18%–24% 宽度；
- 书桌：右侧 24%–30% 宽度；
- 四个热点之间必须保留至少 6% 画布宽度的视觉间隔。

### 3.2 视觉动线

默认视线顺序为：

1. 窗外最亮的天空或夕阳；
2. 窗光落点与桌面；
3. 书架和照片墙上的高饱和色小物件；
4. 收音机的指示灯；
5. 前景中暗色但可辨识的生活物件。

禁止四个热点全部使用同样大小、同样亮度的标签。标签只在悬停、聚焦或触摸后出现，静态画面优先展示美术。

### 3.3 空间层次

场景至少由以下六层构成：

| 层级 | 内容 | 视差强度 |
| --- | --- | ---: |
| `sky` | 天空、云、太阳、月亮 | `0.10` |
| `outside` | 城市、远山、树影、街灯 | `0.18` |
| `room` | 墙、窗框、地板、固定结构 | `0.30` |
| `objects` | 书架、照片墙、书桌、收音机 | `0.55` |
| `light` | 窗光、台灯光、尘埃、反射 | `0.72` |
| `foreground` | 桌沿、椅背、植物、散落物件 | `0.90` |

视差只做 4–12px 的轻微移动，不允许图层错位到露出透明边界，也不允许大幅晃动画面。

## 4. 色彩与光影

### 4.1 色彩原则

- 单一状态的核心色不超过 18 种，局部物件可以使用 2–3 种强调色；
- 暗面不是纯黑，统一使用带蓝紫或青绿色的有色阴影；
- 高饱和色只用于太阳、灯、书脊、照片、收音机指示灯和少量生活物件；
- 窗外和室内必须有明确冷暖关系；
- 任何新增物件先归入色板，再决定细节颜色，不允许随意添加颜色。

### 4.2 黄昏主色板

| 用途 | 色值 | 用法 |
| --- | --- | --- |
| 夜蓝暗面 | `#1d2038` | 房间深处、轮廓、家具背光面 |
| 紫灰墙面 | `#34304b` | 后墙和窗框阴影 |
| 蓝紫中间色 | `#51466b` | 地板、布料、远景建筑 |
| 暖棕木色 | `#805b4f` | 书架、桌面、窗框 |
| 玫瑰暗红 | `#a55666` | 云层、海报、家具点缀 |
| 夕阳橙 | `#e17b58` | 天空低处、光线过渡 |
| 金色高光 | `#ffb45f` | 太阳、台灯、窗光边缘 |
| 奶油亮部 | `#ffe0a0` | 最亮窗光和小灯 |
| 植物绿 | `#627b68` | 盆栽和少量远景树叶 |
| 反射青 | `#668897` | 窗玻璃、夜景和金属小面积反光 |

### 4.3 四种时间色板变化

| 状态 | 天空 | 室内暗面 | 主要光源 | 氛围关键词 |
| --- | --- | --- | --- | --- |
| 清晨 | 灰蓝、淡粉 | 冷紫灰 | 窗外漫射光 | 安静、刚醒、薄雾 |
| 午后 | 蓝天、奶白云 | 中性棕灰 | 大面积自然光 | 清爽、开放、明亮 |
| 黄昏 | 橙红、玫瑰紫 | 深蓝紫 | 低角度窗光 | 温暖、停留、故事感 |
| 夜晚 | 深蓝、青黑 | 蓝黑、紫黑 | 台灯、屏幕、街灯 | 安静、私密、微光 |

### 4.4 光影规则

- 黄昏窗光从窗户向右下或左下斜射，方向保持稳定；
- 窗光不是一块纯色矩形，应由宽光带、家具遮挡和地面碎光组成；
- 物件受光边保留 1–2 基准像素的金色轮廓；
- 前景物件的投影使用蓝紫色，不使用黑色硬块；
- 夜晚优先保留局部发光，不把整个房间简单套一层黑色滤镜；
- 光影图层可以通过透明度和混合模式变化，但不能造成像素边缘模糊。

## 5. 场景资产规范

### 5.1 窗户与窗外

窗户是主视觉，不是背景装饰。

- 大窗占后墙宽度的 48%–64%；
- 窗框必须有厚度、内侧暗面和窗台；
- 窗外至少包含天空、远景、近景三层；
- 黄昏：太阳或最亮天空位于窗户偏右/偏左三分之一处；
- 夜晚：远处至少有 3–6 个不同亮度的窗灯或街灯；
- 城市轮廓使用不规则楼顶，禁止连续重复的矩形楼块；
- 可选加入电线、树影、雨痕、鸟或远处车辆，但每次最多使用两类动态元素。

### 5.2 书架（`anime`）

书架是左侧最强的内容入口。

- 五层木架，带侧板、顶板和底部阴影；
- 每层 4–8 本书，书脊高度、倾斜角和颜色不完全重复；
- 至少有 2 张海报、徽章或小摆件暗示番剧兴趣；
- 书脊使用红、金、青、紫作为少量高饱和点；
- 书架背板比书脊暗 15%–25%，让书本脱离背景；
- 书架热点覆盖整个书架，但不遮挡书脊细节；
- 进入小游戏后，书架可增加一条微弱的金色轮廓或亮灯反馈。

### 5.3 照片墙（`photo`）

- 使用绳线、夹子、胶带或不规则相框，不使用整齐网格；
- 3–6 张照片，尺寸和旋转角略有差异；
- 照片内容用抽象像素图表达街景、人物背影、海边或天空；
- 避免出现真实姓名、真实敏感信息或未经处理的个人照片；
- 其中一张可以使用强烈夕阳色，作为与窗外光线的呼应；
- 照片墙的整体亮度低于窗外，但高于深色墙面。

### 5.4 书桌（`notes`）

- 桌面必须有前后厚度和桌下投影，不能是一条横向矩形；
- 至少包含显示器/笔记本、纸张、笔、杯子、相机或键盘中的四项；
- 台灯是夜晚第二视觉焦点，灯罩、灯杆、底座和光池要可辨；
- 屏幕使用冷青色小面积发光，避免成为整个画面最亮处；
- 桌面物件以 2–3px 像素高光表现材质，不使用真实反射贴图。

### 5.5 收音机（`memo`）

- 放在右侧或桌面前景，轮廓必须区别于普通方块；
- 机身、扬声器格栅、旋钮、天线、指示灯至少五个结构细节；
- 黄昏使用暗红/棕红机身，夜晚增加暖色指示灯；
- 点击后可以出现微弱的波纹、灯光或文字提示，但不自动播放声音；
- 视觉上代表小木专栏和随笔，不使用过多文字。

### 5.6 前景与生活痕迹

前景负责把“房间”变成“有人生活的房间”。建议从以下物件中选择 6–10 项：

- 椅背、桌沿、床角或地毯；
- 盆栽、耳机、相机、胶卷、书本、线缆；
- 杯子、便签、游戏手柄、纸箱、窗帘；
- 一盏远处的街灯、一只飞蛾或玻璃上的雨痕。

每个物件都必须服务构图或叙事，禁止为了“填满画面”随机堆放。

## 6. 时间状态与动态

### 6.1 状态规则

四种状态共享物件布局和热点坐标，仅替换或调整：

- `sky`、`outside` 和少量远景资产；
- `light` 的颜色、方向和透明度；
- 台灯、屏幕、街灯和收音机指示灯；
- 云、雨、星星、尘埃等低成本氛围元素。

不得为了切换时间重建整棵 DOM/SVG 场景树。

### 6.2 动态预算

- 默认只允许 3 类动态：视差、光影呼吸、少量氛围粒子；
- 粒子数量桌面端 24–48 个，移动端 8–16 个；
- 动画周期 4–16 秒，禁止快速闪烁；
- `prefers-reduced-motion: reduce` 时关闭视差、粒子和光影呼吸，只保留状态切换；
- 触摸设备以拖动镜头为主，不使用持续自动摇镜头；
- 所有动态必须不影响热点按钮的点击区域。

### 6.3 动态场景设计

场景必须具备持续但克制的生命感。动态不是播放视频，也不是让整张图片每帧重绘，而是让少量图层和像素对象产生节奏明确的变化。

#### 6.3.1 动态类型

| 动态 | 适用状态 | 实现方式 | 视觉强度 |
| --- | --- | --- | ---: |
| 图层视差 | 全部 | CSS `transform` + 指针/触摸位置 | 低 |
| 云层缓移 | 清晨、午后、黄昏 | 独立远景图层平移 | 极低 |
| 窗光呼吸 | 黄昏、夜晚 | 光影图层透明度变化 | 极低 |
| 尘埃漂浮 | 黄昏、午后 | 小型 Canvas 或 DOM 像素粒子 | 低 |
| 窗帘/植物轻摆 | 清晨、黄昏、夜晚 | 2–3 帧 sprite 或 CSS 位移 | 低 |
| 台灯/屏幕微光 | 夜晚 | 局部光层透明度变化 | 低 |
| 收音机指示灯 | 夜晚、交互后 | 像素帧动画或 CSS 闪烁 | 低 |
| 远处车辆/街灯 | 夜晚 | 小型精灵沿预设路径移动 | 极低 |
| 雨滴与玻璃反光 | 夜晚，可选 | 独立透明图层 | 低 |
| 热点聚焦推进 | 点击区域后 | CSS 缩放、平移和暗角 | 中 |

#### 6.3.2 默认黄昏动态

默认黄昏状态至少包含以下四项：

- 窗外云层以极慢速度水平移动；
- 夕阳光带以 8–14 秒周期轻微呼吸；
- 24–48 个低对比度尘埃像素沿缓慢路径漂浮；
- 窗帘、植物或桌面纸张产生非常轻的摆动。

动态不能抢过窗外夕阳和室内四个核心物件。任何单个动态元素的亮度变化不超过其基础亮度的 15%。

#### 6.3.3 夜晚动态

夜晚不是把黄昏整张图降低亮度，而是提供独立的局部光源和城市节奏：

- 远处建筑中 3–6 个窗口或街灯以不同时间点亮起；
- 偶尔有一枚车辆光点沿窗外街道横向掠过；
- 台灯形成小范围暖色光池，屏幕保持冷青色微光；
- 收音机指示灯每 3–6 秒缓慢闪烁，不使用高频闪烁；
- 可选加入雨滴、玻璃反光或屋檐滴水，但最多启用两类雨景动态。

#### 6.3.4 交互动态

点击热点后，动态应该帮助用户理解“镜头正在靠近”：

1. 非目标图层透明度降低到约 70%；
2. 目标图层轻微放大，最大缩放不超过 `1.08`；
3. 目标区域的窗光、台灯或指示灯出现一次短暂强调；
4. 过渡结束后才打开小游戏或更新入口提示；
5. 点击“回到房间”时使用相同过渡返回全景。

书架小游戏完成后，书架增加金色边缘光和一帧短促的“点亮”反馈，但不能永久改变原始构图。

#### 6.3.5 动态实现边界

- 静态插画图层使用 PNG/WebP，不在每帧重新绘制；
- 视差、透明度和位移优先使用 CSS transform/opacity；
- 粒子只在独立的小型 Canvas 或少量 DOM 节点中运行；
- 需要逐帧变化的物件使用 2–4 帧 sprite，不制作长视频背景；
- 所有动画都必须在场景容器内部运行，不能影响页面滚动和导航；
- `prefers-reduced-motion: reduce` 时停止视差、粒子、呼吸、车辆和雨滴，仅保留静态场景与点击后的必要焦点切换。

### 6.4 场景切换

- 手动选择立即切换颜色与光影，过渡时长 400–800ms；
- 自动模式根据本地时间选择状态，每 60 秒检查一次；
- 当前偏好继续存储在 `muxin-wander-scene`；
- 切换不改变用户已探索进度和小游戏状态；
- 夜晚状态必须独立设计，不能只对黄昏图层降低亮度。

## 7. 交互与内容映射

| key | 视觉区域 | 目标地址 | 可选增强 |
| --- | --- | --- | --- |
| `anime` | 书架 | `/wander/anime/` | 打开整理书架小游戏 |
| `photo` | 照片墙 | `/wander/photos/` | 聚焦照片并显示短提示 |
| `notes` | 书桌 | `/wander/notes/` | 聚焦笔记本、显示器和相机 |
| `memo` | 收音机 | `/memo/` | 点亮收音机、显示电台提示 |

行为要求：

- 点击热点先聚焦场景，再更新探索进度；
- 未完成书架游戏时，`anime` 打开小游戏，同时保留“跳过，直接进入”链接；
- 其他区域不被小游戏阻塞；
- 键盘可以通过 Tab 聚焦四个热点，Enter/Space 触发；
- 热点必须有 `aria-label` 或可见文字，不能只依赖画面识别；
- 文字目录始终可见或可在降级入口中打开；
- 屏幕阅读器应能读到场景说明、四个入口和当前探索进度。

## 8. 响应式与降级

### 桌面端

- 展示完整 16:9 场景，最大宽度跟随页面容器；
- 启用 6 层轻微视差、窗光和少量粒子；
- 热点标签默认隐藏，悬停/聚焦后显示；
- 保持场景细节，不用动态模糊模拟景深。

### 移动端

- 保持完整构图，不裁掉窗户、书架或书桌；
- 视差缩小到 2–5px，优先保证触摸热点；
- 粒子和光影动画减少或关闭；
- 热点标签常驻或使用更大的触摸区域；
- 书架小游戏保持可操作，三列布局在窄屏下仍可读。

### 静态降级

- 图片加载失败时显示纯色背景、场景说明和四个文字入口；
- JavaScript 失败时，页面仍提供四个直接链接；
- `prefers-reduced-motion` 不影响图片、文字和热点可用性；
- 不把 WebGL 作为进入内容的必要条件。

## 9. 性能与资源预算

- 首屏主视觉总下载量目标：桌面端 ≤ 500KB，移动端 ≤ 300KB；
- 首屏只加载当前时间状态，其他状态延迟加载；
- 单张图层建议 ≤ 180KB，使用 WebP；
- 动态层不超过 6 层，真正持续动画的层不超过 3 层；
- 不引入额外 3D 引擎或大型绘图库；
- 视差使用 CSS transform，避免每帧重绘整张图片；
- 目标：桌面端稳定 30fps+，移动端保持交互流畅而非追求复杂动画；
- 必须通过 `npm run check`、`npm run build` 和移动端手动验收。

## 10. 资产制作流程

### 阶段 A：构图灰盒

1. 以 320×180 画布确定窗户、书架、书桌和前景比例；
2. 只使用 5–7 种颜色确认明暗关系；
3. 验证四个热点是否拥有清晰的空间位置；
4. 先不加文字、粒子和装饰。

### 阶段 B：黄昏主视觉

1. 完成天空、城市、窗框和地板；
2. 完成书架、照片墙、书桌、收音机四个核心物件；
3. 增加桌面、盆栽、海报和前景小物件；
4. 统一轮廓、暗面和窗光；
5. 导出静态截图检查是否像完整游戏画面。

### 阶段 C：图层化与交互

1. 按六层结构拆分资产；
2. 在 Astro 中组合图层；
3. 迁移现有 `wander-diorama.ts` 的焦点、视差和进度逻辑；
4. 重新校准四个热点位置；
5. 连接现有书架小游戏，不修改存储协议。

### 阶段 D：其他时间状态

1. 从黄昏图层复制布局，不复制整张合成图；
2. 先完成夜晚，再完成清晨和午后；
3. 分别检查窗外光源和室内局部发光；
4. 检查手动切换、自动切换和刷新后的状态恢复。

### 阶段 E：验收与发布

1. 桌面端检查默认黄昏截图；
2. 移动端检查热点和小游戏操作；
3. 检查 `prefers-reduced-motion` 和 JavaScript 失败降级；
4. 运行 `npm run test:storage`、`npm run check`、`npm run build`；
5. 浏览器验收后关闭浏览器进程，再推送部署。

## 11. 验收标准

### 视觉验收

- 默认黄昏画面可以作为游戏截图分享；
- 画面第一焦点是窗光和窗外景，不是按钮或标题；
- 室内至少有前景、中景、远景三种层次；
- 四个区域不用文字也能大致识别；
- 物件细节来自有意义的像素簇，不是随机噪声或重复矩形；
- 黄昏、夜晚、午后、清晨具有明确的色彩和光源差异。

### 交互验收

- 四个热点可点击、可键盘操作、可在移动端触摸；
- 点击书架会打开小游戏，且可以跳过；
- 其他三个入口不受小游戏影响；
- 探索进度、场景偏好和小游戏完成状态刷新后仍然存在；
- 文字目录始终可达。

### 技术验收

- 不依赖 WebGL 才能访问内容；
- 不新增大型依赖；
- 构建无新错误；
- 场景图片和图层加载失败时有可读降级；
- 低内存服务器上不连续进行多次浏览器渲染；
- 浏览器验收后确认 Chromium 退出。

## 12. 扩展体验规范

### 12.1 场景叙事状态

探索不只增加计数，还应让房间产生轻微、可回溯的变化。叙事状态必须存储在现有本地状态体系中，并且不影响直接访问内容。

推荐状态：

| 触发条件 | 场景反馈 |
| --- | --- |
| 首次进入 | 窗边光线较明显，提示从房间开始探索 |
| 探索书架 | 书架增加一盏小灯或一条金色边缘光 |
| 探索照片墙 | 某张照片出现短暂高光 |
| 探索书桌 | 显示器或台灯亮度轻微变化 |
| 探索收音机 | 指示灯点亮并显示一句短提示 |
| 四区全部探索 | 窗外增加一处远景细节或出现一条收束文案 |

变化应保持克制，不得永久遮挡内容，也不得让用户必须完成探索才能访问页面。

### 12.2 微小彩蛋系统

增加 6–10 个不影响主流程的低成本彩蛋，用于鼓励二次探索：

- 窗边偶尔飞过一只鸟；
- 桌下藏着一盘胶卷或一张便签；
- 某本书脊上有特殊符号；
- 收音机偶尔显示一句短文字；
- 夜晚远处某扇窗里出现短暂剪影；
- 盆栽、相机、台灯等物件可以显示极短提示。

彩蛋必须满足：

- 不遮挡四个主热点；
- 不要求用户完成复杂操作；
- 不包含真实姓名、敏感信息或未经处理的个人资料；
- 触发后可记录，但刷新后不应造成主场景错位；
- 首屏不同时展示全部彩蛋，避免画面过度拥挤。

### 12.3 镜头语言规范

每个区域都使用独立的镜头方向、推进距离和停留重点，不能只是统一缩放。

| 区域 | 镜头动作 | 视觉重点 |
| --- | --- | --- |
| 书架 | 向左上方轻微推进 | 书脊、海报、书架灯 |
| 照片墙 | 横向平移并略微靠近 | 照片卡片、夹子、墙面光斑 |
| 书桌 | 向右下方推进 | 笔记本、相机、台灯、屏幕 |
| 收音机 | 短距离正向推进 | 旋钮、扬声器、指示灯 |
| 回到房间 | 缓慢拉远并恢复亮度 | 完整房间和窗外主构图 |

镜头过渡规则：

- 目标区域最大缩放不超过 `1.08`；
- 过渡时长 350–650ms，使用平滑缓动；
- 非目标区域最多降低到 70% 不透明度；
- 过渡完成后再打开小游戏或更新入口提示；
- 用户点击其他热点时应中断当前过渡并转向新目标；
- `prefers-reduced-motion` 下改为即时聚焦，不使用推进动画。

### 12.4 声音预留

声音作为可选增强，不得成为内容访问或理解场景的必要条件。

预留事件：

- 黄昏：低音量风声和远处城市声；
- 夜晚：雨声、远处车辆或街灯电流声；
- 收音机：很短的电流/调频提示音；
- 书架完成：一次短促的像素提示音；
- 点击热点：轻微、非侵入式反馈音。

声音规范：

- 默认静音，不自动播放；
- 提供明显的静音/开启控制；
- 使用短音频文件，不加载连续背景音乐作为首屏依赖；
- 用户关闭声音后，本地记住选择；
- 音效不能覆盖页面文字或造成持续打扰；
- 无音频、自动播放被浏览器阻止或低性能设备上，所有功能仍完整可用。

### 12.5 视觉回归检查

每次修改场景、样式或资源后，固定检查以下状态并保存截图：

```text
黄昏默认状态
夜晚状态
移动端窄屏
书架聚焦状态
小游戏打开状态
减少动态效果状态
```

回归检查至少确认：

- CSS 资源返回 `200`，没有回退到浏览器默认样式；
- 窗户、书架、照片墙、书桌和收音机没有错位或溢出；
- 四个热点仍覆盖正确物件，并且可键盘/触摸操作；
- 时间切换不重置探索进度和小游戏状态；
- 视差不会露出图层边界；
- 移动端的入口、小游戏和文字目录仍然可见；
- 浏览器验收后 Chromium 进程已退出。

4. 为照片墙和收音机增加独立的短过场动画。
